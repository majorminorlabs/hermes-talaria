## Safe recording state

The phone can be launched with `-uiTesting -resetState` into the app's separate
synthetic fixture storage. This preserves the real paired installation and its
private data. It is a demonstration of the accepted UI with synthetic data; do
not describe fixture streaming, Capture persistence or speech as a live bridge test.
Relaunch without arguments to return to the actual Hermes connection. Real host
settings and unfiltered real history must never be filmed.

## Suggested flow

1. Now: show representative Needs You, Working and Done. Fixtures include supplier
   clarifications and a shortlist review. Later says it will reappear without notification.
2. Global Ask: Auto/Hermes route, then explicitly target Research Worker; send a
   planning question and show progress/response.
3. Threads: reopen the two separate Agent sessions; use realistic prompts about
   a morning briefing and a supplier shortlist to distinguish the histories.
4. Agents: list/detail, Ask action, model-default scope and guarded Revert.
5. Voice Ask: demonstrate hold/release or down-to-lock, with cancellation once.
   Real microphone validation was done on the physical phone; fixture mode uses
   synthetic speech input. Switch to the real app only for a controlled live take.
6. Capture: save “Compare the morning briefing with yesterday before planning the
   next sprint.” Show Capture as storage, distinct from Ask execution.
7. Active work: add an instruction, Stop, then show the truthful stopped state.
8. Live Activity: launch with `-TalariaDemo YES` for the finite synthetic aggregate
   sequence, go Home promptly and film the Dynamic Island/Lock Screen if practical.
   It cleans up after the sequence. Relaunch without arguments afterward.

## Setup before each take

Reset only the isolated fixture storage; its timed clarifications expire and
answers/Later mutate the fixture state. A normal source launch restores private
production state. Keep Settings/Studio/host/token screens out of recording.
For a genuine streaming/voice/Capture take, open only a fresh synthetic thread and
check the entire visible screen before recording. Accepted live Alpha/Beta threads
contain only “TALARIA THREAD ALPHA/BETA” prompts and responses; no private context.

Do not show private conversation lists, captured camera surroundings, credentials,
SOUL/configuration text, hostnames or signing/device identifiers. Do not imply
APNs/background monitoring guarantees, stock SideStore expiry validation, physical
iOS 18 validation or any Phase 2 feature. No promotional video was recorded.
